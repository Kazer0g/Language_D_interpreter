# Демонстрации Language D

Команды запускаются из корня репозитория. Для демонстраций нужна сборка с C++17.

```sh
g++ -std=c++17 -Wall -Wextra -o main main.cpp
```

## Лексер

Примеры лежат в [lexer/](lexer/).

```sh
./main --tokens demos/lexer/Demo2
./main --tokens demos/lexer/Demo5
```

В `Demo2` сравни вывод для диапазона и вещественного числа. Лексер
распознаёт `..` как отдельный токен диапазона, а точку с цифрами после неё
как часть вещественного литерала. `Demo5` показывает ошибку при переносе
строки внутри литерала, а `Demo6` — при записи числа как `1.`.

## Парсер

Примеры лежат в [parser/](parser/).

```sh
./main --no-optimize demos/parser/demo1_precedence.d
./main --no-optimize demos/parser/demo4_error_exit.d
./main --no-optimize demos/parser/demo5_error_assign_call.d
```

В первом примере у `1 + 2 * 3` корень дерева — `Binary +`, его правый
потомок — `Binary *`. Так дерево сохраняет приоритет умножения.
Четвёртый пример разбирается парсером и завершается семантической ошибкой
из-за `exit` вне цикла. Пятый останавливается в парсере с синтаксической
ошибкой. Флаг `--no-optimize` пропускает оптимизации, а семантические
проверки выполняются.

## Семантический анализ и оптимизации

Примеры лежат в [analyzer/](analyzer/).

```sh
./main --before-after demos/analyzer/constants.d
./main --before-after demos/analyzer/unreachable.d
```

В `constants.d` выражение `2 + 3 * 4` превращается в узел `Int 14`.
Деление на ноль остаётся в дереве. В `unreachable.d` из тел функций и
циклов удаляются три инструкции после безусловных `return` или `exit`.
Файлы `error_*.d` показывают семантические ошибки в цели присваивания,
вложенной функции и цикле верхнего уровня.

## Как читать код по шагам

1. [main.cpp](../main.cpp#L32) читает файл, разбирает флаги и вызывает
   этапы обработки. Следи за переменными `source`, `tokens` и `program`,
   чтобы увидеть, как меняется представление одной и той же программы.
2. [Lexer::run](../lexer.cpp#L152) идёт по символам, пропускает пробелы
   и комментарии и вызывает `scanToken` для очередной лексемы. У
   каждого токена есть тип и позиция. Чтобы проследить ветвление для
   `Demo2`, начни с `scanNumber`, где проверяется символ после точки.
3. [Parser::parseProgram](../parser.cpp#L231) собирает список инструкций
   `Stmt`, внутри которых выражения представлены узлами `Expr`.
   В выражении `1 + 2 * 3` разбор сложения в `parseFactor` запрашивает
   операнды у `parseTerm`. Именно `parseTerm` собирает `2 * 3` в
   отдельное поддерево ещё до создания узла сложения.
4. [Analyzer::checkProgram и optimizeProgram](../analyzer.cpp#L29)
   обходят дерево в два прохода. Первый проверяет позиции `exit` и
   `return` и форму цели присваивания. Второй обходит выражения от
   дочерних узлов к родителю, чтобы в `2 + 3 * 4` сразу после
   `3 * 4 → 12` свернуть и `2 + 12 → 14`.
5. [printTree](../parser.cpp#L849) печатает AST, после чего
   `destroyProgram` освобождает узлы. Текущая версия заканчивает работу
   на выводе дерева. Инструкции языка, включая `print`, пока ожидают
   реализации исполнения.

Чтобы проследить одну программу от начала до конца, возьми
`demos/parser/demo1_precedence.d` и запусти её с `--tokens`,
`--no-optimize`, а затем с `--before-after`. В последнем выводе
найди, как поддерево `1 + 2 * 3` заменяется на `Int 7`.
